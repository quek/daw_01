M15: text_input を TSF ITextStoreACP として OS IME に公開 (完了 2026-06-01)

Context — なぜ

rtry (F:\dev\rtry) は user 自作の Windows TSF IME (Try-Code)。 focus 中アプリの context に対し GetSelection → Collapse(TF_ANCHOR_START) → ShiftStart(-10) → GetText で カーソル前テキストを読み まぜ書き変換する。winit/wgpu の自前描画 ウィンドウは legacy (非 TSF) app なので msctf の CUAS 互換ストアが任意 range の GetText を 返せず、rtry の GetText が空 = まぜ書きが動かなかった。winit は WM_IME_REQUEST も 未処理なので MS-IME 再変換も無反応だった。

結論: gui_01 platform 層に TSF ITextStoreACP document store を 1 つ実装 すれば、rtry・MS-IME・ATOK 全 TIP に対し GetText / 再変換 / 候補位置 / document feed が一括で通る。 Windows 限定 (既存 IME workaround も Windows 限定)。

アーキテクチャ

モジュール (crates/platform/src/)

  • acp_map.rs — UTF-16 ACP ⇔ UTF-8 byte の純粋マッピング (サロゲート/CJK/emoji)。全 OS で単体テスト。
  • text_document.rs — 中立型 TextDocument / ImeTextEdit / RectPx。
  • tsf/doc_state.rs — DocState: キャッシュ snapshot + 編集キュー + echo 抑制 diff (COM 非依存・単体テスト)。
  • tsf/text_store.rs — #[implement(ITextStoreACP)] DocumentStore (薄い COM shim)。
  • tsf/thread_mgr.rs — TsfManager: CoInitialize(STA) → ThreadMgr Activate → Context → Push → AssociateFocus。

実装するのは ITextStoreACP ストアのみ。msctf が ITfRange/ITfContext/view を合成し、 rtry の ShiftStart/GetText/SetText/GetTextExt を我々の ACP メソッドに翻訳する。

immediate-mode ↔ 長命 store の同期

IME は ITextStoreACP をメッセージポンプ中の任意タイミングで同期呼び出しするが、 text_input は frame() 中にしか存在しない。DocState がキャッシュ snapshot を保持し:

  • publish (UI→store): focus 中 text_input が毎フレーム Ui::publish_text_document(text, sel, caret) → frame() 末で WindowBackend::set_text_input_document に flush (cursor flush と同じ transient 経路)。
  • drain (store→UI): IME の SetText/InsertTextAtSelection は byte 空間の ImeTextEdit をキューに積む → 次フレーム頭で ImeEvent::ReplaceRange / SetSelection に 変換して text_input が replace_range(min..max, new) 不変条件で適用。
  • echo 抑制: IME 自身が最後に set した値 (last_ime_*) を覚え、widget が echo back する間は OnTextChange/OnSelectionChange を抑制 (通知ストーム防止)。

caller boilerplate ゼロ: 既存の「app が ime_request() で set_ime_allowed を駆動」 contract は不変 (TSF は純粋に additive)。daw_01 は無改修で TSF を得る。

既知の罠 (実機で踏んだ)

  • AssociateFocus 必須 (SetFocus だけでは不可): SetFocus(doc_mgr) は thread の focus doc を設定するが document を HWND に束縛しない。window が OS focus を得ると msctf は CUAS の既定 document を使い、TIP の編集が我々の store に届かない (症状: rtry ログで ShiftStart(-10) shifted=0 / TSF read failed, using postbuf fallback、変換が postbuf の backspace 再現にズレる)。 ITfThreadMgr::AssociateFocus(hwnd, doc_mgr) で束縛して解決。
  • winit はデフォルト IME 無効: 生成時 set_ime_allowed(window, false) される。focus 中に app が set_ime_allowed(true) を呼ばないと IME を ON にできない (TSF doc focus だけでは不足)。
  • STA は winit が保証: winit が OleInitialize で event loop スレッドを STA 化するので、 CoInitializeEx(APARTMENTTHREADED) は S_FALSE (既に STA) を返す = 正常。RPC_E_CHANGED_MODE 時のみ TSF 無効化 + IMM fallback。
  • AcpMap::default() underflow: #[derive(Default)] だと Vec が空になり len16() の len()-1 が underflow panic (DocState::new() が踏む)。Default を build("") 相当 (sentinel [0]) に手実装 + saturating_sub 防御。invariant 型は Default/空構築もテストする。
  • COM shim の lint: windows API の wildcard import / #[implement] マクロ生成 (inline_always) / ACP i32 cast / out-param raw pointer は不可避 → COM module 単位で #![allow(...)]。
  • 非 Send 維持: TSF COM は STA / Rc 保持で非 Send。WinitWindow (Send 要求) に持たせず UI スレッド thread-local (TsfSlot: Untried/Failed/Active) に置く。
