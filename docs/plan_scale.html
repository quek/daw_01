2. 大方針

daw_01 は「時間軸上の scale change event (Cubase 流) を Song 直下に持つ」 + 「3 軸で独立に scale 拘束を ON/OFF (Cubase 流: 描画時 / Live 入力 / 一括補正)」 + 「Fold to Scale (Ableton 流)」 を採用する。 度数別カラー (Bitwig) と Chord Track / Scale Suggestions (Cubase) は scope 外。

  • SSoT は Song.scale_changes: Vec<ScaleChange>。 Clip 単位 / Track 単位 / プロジェクト global を別々に持つと SSoT 違反 (CLAUDE.md)。 1 本のタイムラインで「beat = 0 から最初の event」 → 「次の event でルート変更」 ... と表現する。
  • 転調 (key change) は scale_changes に 2 件目以降を追加するだけ。 Cubase の Scale Event と同じく次の event 開始まで有効。
  • 無設定 (scale_changes 空) = constraint OFF / chromatic 互換 = 既存の挙動と完全互換。 新規ユーザは Scale 機能を意識せず使える。
  • UI は段階的に増やす。 最初は Transport の「現在の root + scale 表示 + dropdown」 と Piano Roll の鍵盤ハイライト + Fold だけで十分実用。 Arrangement の Scale Lane (Chord Track 風) は後段で追加。
  • 3 軸 constrain は完全に独立 toggle (Snap on Draw / Snap Live Input / Quantize Pitches)。 Cubase の三分法が最も明快で、 「描画は scale 拘束したいが Live 入力は半音単位で record したい」 等の運用にも対応できる。

3. データモデル

3.1 Scale enum

業界標準で実用十分な 22 種類 + User を内蔵。 daw_01 側は enum Scale 1 個と「ルート起点 12-bit pitch class mask」 への変換 1 個で扱う (= Scale ごとの値はテーブルから取る、 SSoT)。 Bitwig 23 種類と Cubase 22 種類の合集合をベースに、 ジャズ / ワールド系を一部刈り込む。

// common/src/scale.rs (新設)

#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash, Serialize, Deserialize, Encode, Decode)]
pub enum Scale {
    // 教会旋法 (Ionian/Aeolian は Major/NaturalMinor として後段に置く)
    Major,            // = Ionian
    NaturalMinor,     // = Aeolian
    Dorian,
    Phrygian,
    Lydian,
    Mixolydian,
    Locrian,

    // マイナー系
    HarmonicMinor,
    MelodicMinor,     // 上行のみ (ジャズで一般的な扱い)

    // ペンタトニック / ブルース
    MajorPentatonic,
    MinorPentatonic,
    Blues,            // minor pentatonic + b5

    // 限定的だが業界標準
    WholeTone,
    Diminished,       // whole-half (8 音)
    HalfWholeDim,     // half-whole (8 音、 ドミナント上で頻出)
    Chromatic,        // = 12 全部 in-scale (= snap 効かないが Highlight は root のみ強調)

    // ジャズ / ワールド系
    HarmonicMajor,
    DoubleHarmonic,   // Byzantine
    LydianDominant,   // = MelodicMinor の 4 度
    MixolydianBflat9, // Phrygian Dominant (Spanish)
    Hungarian,        // Hungarian Minor
    Japanese,         // In-Sen (都節)

    // ユーザ定義: ルート起点の 12-bit pitch class mask
    Custom(u16),
}

impl Scale {
    /// ルート起点で「半音 d (0..=11) が in-scale か」を返す 12-bit mask。
    /// 例: Major = 0b0000_1010_1011_0101 (C, D, E, F, G, A, B = bits {0,2,4,5,7,9,11})
    pub fn pitch_class_mask(self) -> u16 {
        match self {
            Scale::Major => 0b1010_1011_0101,
            Scale::NaturalMinor => 0b0101_1010_1101,
            // ... テーブル化、 Bitwig / Cubase 公開仕様に従う
            Scale::Custom(m) => m & 0x0FFF,
            // ...
        }
    }

    /// 表示名 ("Major" 等)。 i18n は当面英語固定。
    pub fn display_name(self) -> &'static str { ... }
}

3.3 query API

「playhead 位置 / 任意 beat / 任意 Note の scale」 は 1 関数で取れるようにする。 audio engine / piano_roll / VOICEVOX いずれも同じ entry point を経由。

// common/src/scale.rs

impl Song {
    /// 指定 beat における active な scale を返す。 該当 event が無ければ None
    /// (= 機能 OFF、 chromatic 扱い)。
    pub fn scale_at(&self, beat: f64) -> Option<&ScaleChange> {
        self.scale_changes
            .iter()
            .rev()
            .find(|c| c.beat <= beat)
    }
}

impl ScaleChange {
    /// 指定 MIDI pitch (0..=127) が in-scale か。
    pub fn contains(&self, pitch: u8) -> bool {
        let d = (pitch as i32 - self.root as i32).rem_euclid(12) as u16;
        (self.scale.pitch_class_mask() >> d) & 1 == 1
    }

    /// 最寄りの in-scale な pitch を返す。 同距離なら上向きを優先 (Cubase 流)。
    pub fn snap(&self, pitch: u8) -> u8 { ... }

    /// scale 度の整数 (0 = root、 1 = 2nd、 ...) で pitch を transpose。
    /// Bitwig の "Shift by Scale Steps" 相当 (将来の Note FX で利用)。
    pub fn step_transpose(&self, pitch: u8, steps: i32) -> u8 { ... }
}

3.4 互換性 (CURRENT_VERSION)

  • CURRENT_VERSION 10 → 11 に bump。 schema 変化 = Song.scale_changes 追加 + Scale enum 新設。
  • #[serde(default)] で v10 ファイルは空 Vec で forward-migrate (= Scale 機能 OFF、 既存挙動完全互換)。
  • Migration は不要。 「最初に Scale UI を触ったとき beat = 0 の event を 1 件追加」 が自然な lazy initialization。
  • Scale enum に variant 追加するときは bincode が tag-based なので新 variant が末尾に居れば前方互換可。 末尾追加を idiom とする (Rust 標準慣習)。

4. UI

UI は 4 箇所。 段階実装 (§9) の順で増やす。

4.1 Transport bar — 現在位置の root + scale 表示 + dropdown

  • BPM / time_sig の隣に「C Major」 形式の small label を追加。 click で root + scale dropdown を開く。
  • 表示する値は playhead 位置の scale_at(playhead_beat)。 Cubase 流 (Chord Track event は playhead に追随)。 再生中は自動で current scale が変わるので転調が視覚的に追える。
  • dropdown commit = scale_changes に対する変更:
    • scale_changes が空 → beat = 0 の event を新規追加
    • scale_changes が 1 件 → その event の root / scale を更新
    • scale_changes が複数 → playhead 直前の event (= scale_at(playhead_beat)) を更新。 「ここで転調を変更したい」 を直感的に達成 (Cubase Transport の Chord Track edit と同じ)
  • 右クリックで "Insert key change here" / "Remove key change here" menu。 細かい時間軸編集は Arrangement Scale Lane (§4.2) 経由。
  • scale_changes が空のときは「No Key」 表示 (Bitwig 流の「無設定」 を明示)。 click で初期 scale (C Major) を提案する dropdown。

4.2 Arrangement Scale Lane (Cubase Chord Track 風、 後段)

  • arrangement view の上端 (ruler 直下、 既存の Master row があれば直下) に「Scale」 という専用 lane を 1 本挟む。 toggle で表示/非表示 (default ON、 scale_changes が空でも lane は出る)。
  • Scale event は ピンのような UI (Cubase の Scale Event と同 idiom)。 横位置 = beat、 ラベル = "C Major"。 隣の event 開始まで背景 band を薄い tint で塗る (= どこからどこまでが C Major か視覚化)。
  • 操作:
    • 左クリック → event 選択 + dropdown popup で root / scale 編集
    • 左ドラッグ → event を時間軸方向に移動 (snap 適用)
    • 右クリック → "Delete" / "Duplicate"
    • lane 空白部 dbl-click → 該当 beat に新 event 追加 (直前の event の root/scale を継承)
  • これは arrangement widget の lane 概念拡張になるので gui_01 widget 側に拡張要望が必要 (§8 参照)。

4.3 Piano Roll header — 現在 scale 表示 + toggle 群

  • piano_roll widget の header (snap toolbar の右、 既存空き領域) に以下を追加:
    • 「C Major」 label (Transport と同期、 click で同 dropdown)
    • Highlight toggle (鍵盤レーンの scale 行ハイライトを ON/OFF、 default ON)
    • Fold toggle (Ableton K キー相当、 out-of-scale 行を非表示、 default OFF)
    • Snap on Draw toggle (§5.1)
  • Live 入力 snap / 一括 quantize は piano_roll ヘッダではなく、 Live 入力 = transport bar の Record 周辺、 一括 quantize = 右クリック menu (§5)。
  • 表示する scale は piano_roll の view start_beat (= clip start_beat + scroll) ではなく playhead 位置。 ただし piano_roll で編集中の clip が playhead と離れているときは「clip.start_beat 位置の scale」 を表示するほうが直感的 (= 編集中の場所の scale を出す)。 段階 S2 では simply playhead で開始、 ユーザフィードバックで切替。

4.4 Piano Roll 鍵盤レーン — 行ハイライト / dim / fold

piano_roll widget の左端鍵盤レーンと、 ノート描画領域の背景の両方に、 scale 情報を反映する。

  • Root 行: 鍵盤の C / C# / ... ラベル背景を強調色 (Bitwig 流: 黄み or 暖色 tint)。 ノート領域も同じ y 位置に薄い tint。
  • In-scale 行: 通常の白鍵 / 黒鍵 表示 (= 既存挙動)。 ただし黒鍵が in-scale (例: D♭ Major の D♭) なら少し明るく、 白鍵が out-of-scale (例: D♭ Major の F) なら少し暗く。
  • Out-of-scale 行: alpha 50% 程度に dim、 もしくは灰色 overlay (Cubase "Show Scale Note Guides" 風)。
  • Fold mode (toggle ON): out-of-scale 行を行リストから除外し、 ピアノロール全体が in-scale 行のみで構成される。 7 音 scale なら 12 行 → 7 行になり、 縦に圧縮されたコンパクト表示。 既存ノートが out-of-scale なら fold mode 中も「上下隣の in-scale 行の間」 にはみ出して表示する (Ableton と同じく、 fold mode は描画だけの変更で実データは触らない)。
  • Fold mode は視覚専用。 マウスでの note 追加 / drag / 既存ノートの編集は依然 in-scale 行ベースで動く (fold 中に Alt 押下で out-of-scale 行に「割り込む」 等は段階 S6 以降の拡張)。

5. 入力 constrain (3 軸)

Cubase の三分法を採用。 3 軸とも独立 toggle、 全 default OFF (= 既存挙動互換)。 toggle 状態は session-only (project save しない)。 各軸の責務:

軸対象UI 位置挙動

S-LiveMIDI 録音 中の note_onTransport bar の Record button 隣に「Snap Live」 togglerecord_midi_note_on(pitch) 直前で snap。 録音前 step input (= キーボード / MIDI で listen 中) は 適用しない (= ピッチを「聞いて」決めるため。 Cubase は Snap Live Input は recording 時のみ)

5.1 Snap on Draw

  • 適用箇所: AppEvent::AddNote { pitch, ... } handler (daw_01 では app.rs::add_note)。 handler 冒頭で scale_at(beat).snap(pitch) を経由。
  • drag-resize / drag-move でも適用したい (= note の y 軸 drag で pitch 変更)。 piano_roll widget が emit する PianoRollEditRequest::Move / Add の pitch 値を caller (daw_01) 側で受け取った直後に snap。 widget 側で snap させる必要は無い (= widget は scale を知らなくて済む)。
  • Alt 押下中は snap 一時無効 (gui_01 既存の Alt = snap bypass の idiom を踏襲)。

5.2 Snap Live Input

  • 適用箇所: daw_gui::app::record_midi_note_on(track_id, pitch, velocity) 冒頭で scale_at(playhead_beat).snap(pitch)。
  • note_off は note_on の pitch を active_recording_notes map で参照する作りなので、 note_on で snap した値を保存しておく。
  • step input (= recording 停止中の MIDI 入力 / キーボードで note 追加) には適用しない。 step input は pitch を「聞きながら選ぶ」 用途で、 強制 snap すると意図しない音が出る (Cubase / Bitwig も同じ判断、 step input は scale 拘束外)。

5.3 Quantize Pitches

  • 適用箇所: 新 AppEvent::QuantizePitchesToScale { target: PitchTarget } (undoable)。 PitchTarget は SelectedNotes / ClipAllNotes(ClipRef) / SongAllNotes。
  • handler: 対象 note の pitch を scale_at(note.start_beat).snap(pitch) で書き換える。 note の start_beat 時点の scale を使う (= 転調をまたぐ note も自然に補正される)。
  • UI 経路 (段階的に増やす):
    • piano_roll で note を右クリック → "Quantize Pitches to Scale" (選択 note)
    • piano_roll header のメニューに "Quantize all to Scale" (clip 全 note)
    • arrangement の clip 右クリックに「Quantize Pitches」 (MIDI clip のみ表示)
  • Bitwig の "Quantize Up" (= 最寄り上の in-scale) vs "Smart Quantize" (= 音楽的方向の最寄り) は 段階 S6 以降。 S5 では single mode (最寄り / 同距離なら上) で開始。

6. VOICEVOX 連携

VOICEVOX は Note.pitch: u8 をそのまま VOICEVOX engine の FrameAudioQuery.notes[].key に渡している (= 微分音は持たない)。 つまり Note.pitch 自体が in-scale ならそのまま正しく歌う。

  • S-Draw / S-Live / Q-Pitch が note.pitch を in-scale に keep していれば、 VOICEVOX 経路に追加のロジックは不要 (= シンプル)。
  • VOICEVOX synth 経路で追加で適用すべき変換は無い。 「ピアノロールで scale 拘束を外した状態で out-of-scale な note を打ち込んだ」 ユーザは、 意図して out-of-scale を入力している (= 装飾音 / 経過音 / ブルーノート 等) ので、 synth で勝手に snap すると意図に反する。
  • ただし歌詞 → ノート割り当てのような将来的な機能 (= 自動でメロディを生成する系) を入れるなら、 そこで scale を query するのは自然。 S6 以降の検討。

7. audio engine / plugin host への影響

  • scale は純粋に GUI 層の概念。 audio engine / plugin host / MIDI 出力には影響しない (= note は既に snap 済の pitch で送信される、 host 側で再 snap する必要なし)。
  • plugin に scale 情報を渡す経路 (= CLAP clap_event_transport_t や VST3 ProcessContext に scale info 拡張) は標準で無い。 Bitwig の Note FX は Bitwig 内部 protocol で global key を購読する独自仕様。 標準 plugin はそもそも scale を解釈しないので IPC で送る必要なし。
  • = IPC protocol (MainToChild / ChildToMain) には追加変更不要。 daw_audio / daw_plugin_host のコードは触らない。

10. Out of scope (明示的に作らないもの)

  • Chord Track (Cubase): scale event とは別に「コード進行」 を時間軸に持つ機能。 daw_01 では当面 scale 機能で十分、 Chord Track は別 plan で検討。
  • Scale Suggestions / 自動検出 (Cubase): MIDI clip から最有力 scale を統計推定。 後付けで価値はあるが S1-5 と独立。
  • Bitwig の Note FX 連携 (per-device "Use Global Key"): daw_01 は MIDI FX チェーン concept をまだ持たない (M2 では plugin chain は audio FX のみ)。 MIDI FX 導入時に再検討。
  • 度数別カラー (Bitwig "Adapt to Key" 背景モード): root / 3rd / 5th 等を別色表示する高度な視覚化。 §4.4 の root / in / out 三段階で実用十分、 度数別は将来の polish。
  • Scale device / 強制 fold MIDI plugin (Ableton Live Scale device 相当): daw_01 では input constrain で十分と判断 (= note 追加時点で snap する、 リアルタイムにフィルタする必要なし)。 ライブ演奏 (= 既存の MIDI input + dawの外部 MIDI ルート) で強制 fold したい用途が出てきたら別 plan。
  • VOICEVOX 歌詞自動メロディ: 歌詞だけ入れて自動でメロディが scale から決まる、 のような生成系。 別 plan。
