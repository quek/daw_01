## 1. オートメーションの線がドラッグ中 2 重に見える (未解決)

**症状**: 線を Alt+ドラッグして曲げている最中、元の曲線と曲げ後の曲線が 2 本見える。

**入れた修正 (効いていない)**: `2c3c668`。ドラッグ中はその 1 区間だけ cached レイヤが
base curve を描かないようにし (`HeavyInput` の skip)、`viewport_key` にその区間の key を足した
(key はドラッグの開始と終了でしか変わらないので、hover のような毎フレーム再構築にはならない)。

**次に疑うところ**:
- テストは「その区間に曲線の線分が 2 組積まれていない」を見ている。実機で 2 本見えている以上、
  **2 本目が別経路から来ている**可能性が高い。cached / overlay 以外に automation curve を描く
  経路が無いかを洗う (`draw.rs` の lane 描画、選択オーバーレイ、preview の二度描き)。
- skip の条件が「掴んでいる区間」と一致しているか。lane / clip / point の key の取り違えがあれば
  skip が空振りして base が残る。
- 実機の 2 本が「元 vs プレビュー」なのか「プレビューの二度描き」なのかを、
  まず色と太さで見分ける (プレビューは `automation_curve_bend_preview_color` で線幅 1.5 倍)。

## 2. ゲインドラッグ中に dB ハンドル線が消える (未解決・revert 済み)

**症状**: ゲインをドラッグすると横線が 1 本も出ない。

**状態**: `0edd42a` で 1 本化を試みたが実機で線が消えたため **`3de6980` で revert 済み**。
main は「2 本見える」元の挙動に戻っている (悪化はしていない)。

**入れようとした修正**: 曲線と同じ機構。`HeavyInput::gain_drag_skip` で cached 側の
dB ハンドル線を描かず、ゴースト側だけを描く。`viewport_key` を v8 → v9。
`kind == Gain` のときだけ skip (fade 系のドラッグは dB 線を動かさないため)。
ゴーストは「anchor と同値でも描く」ようにした (でないと掴んだ値をまたぐたびに点滅する)。

**次に疑うところ**:
- **skip の条件が広すぎて、ドラッグしていないときにも効いている**のではないか
  (= 常時 base が描かれない)。掴む前のフレームで線が出ているかを実機で確認するのが早い。
- ゴースト側が「outcome が None でも描く」に本当になっているか。revert 前の diff を
  `git show 0edd42a` で読み直す。
- テストは 4 フレーム (掴む前 / ドラッグ中 / anchor へ戻す / release) を見ていたので、
  **テストが通ったのに実機で出ない = テストの駆動経路が実機と違う**可能性がある。
  `daw_gui/tests/arr_widget.rs` は `UiHost::frame` 経由。実機は `view::root::build_root` 経由なので、
  `automation_hover_visual.rs` がやっているように **実機と同じ経路で組む**ほうが確実。

**ゲインドラッグの操作方法** (実機確認用): オーディオクリップの中央を横切る細い横線を上下にドラッグする。
掴める帯は上下中央 ±4px、左右の端から 24px 内側。クリップ幅 32px 未満は無効。フェードの角の四角が優先。
